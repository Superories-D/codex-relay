# Git hunk staging — 2026-10-18

Source milestone after v0.6.17 and the managed Git concurrency fixes. Existing
release artifacts, installed client and real profiles remain unchanged.

## Workflow

The Changes panel provides a stage/unstage button beside each eligible text hunk.
It keeps the current staged/working view while more changes remain on that side.
The buttons have numbered accessible names, support keyboard activation and use
the existing four-language catalog, including Japanese. Whole-file actions remain
available. Unsupported diff types explicitly direct users to whole-file actions.

The main process regenerates the selected file's diff, checks the reviewed Git
revision and full preview, and extracts the selected hunk from that fresh output.
It never executes a patch supplied by the renderer. The operation shares the
canonical-Worktree queue introduced in `GIT-CONCURRENCY-20261018.md`.

The patch is passed on stdin to `git apply --cached --whitespace=nowarn`, reversed
for unstaging. This changes the index without changing working files; a failed
apply does not use partial-reject or automatic conflict-resolution modes. These
semantics follow the [official Git apply documentation](https://git-scm.com/docs/git-apply).
Diff paths and context are explicitly configured so user prefix/context settings
do not turn the reviewed patch into an incompatible or unexpectedly merged hunk.

## Remaining scope

This stages whole hunks, not selected individual lines within a hunk. Rename/copy,
mode-change, symlink, submodule, combined-conflict, binary and undecodable text
diffs retain whole-file operations. Literal Unicode replacement characters also
conservatively disable hunk reconstruction. New untracked files can be staged as
a whole file; intent-to-add and already-staged text additions are supported.

The existing 4 MiB Git-output bound and external-process race limits remain;
this is not a claim of unlimited large-diff performance or filesystem-wide
transaction isolation. Advanced conflict/PR workflows and live-account gates
remain in `RELEASE-READINESS.md`.
