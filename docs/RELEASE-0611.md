# v0.6.11 Windows 交付

本轮按用户要求收尾、打包并暂停持续 Goal。产品仍处于逐项打磨阶段，不声明已完整复刻 Codex Desktop。

## 模型路由

- 账户保存有时效的原生模型目录，包含分页和别名；重复游标、空目录、部分目录和过期目录不作为拒绝证据。目录匹配优先于账户价值/顺序轮换评分，未列出的模型仍允许实际请求。
- 仅识别已真实验证的原生错误格式：`invalid_request_error` / HTTP 400，明确声明当前 ChatGPT 账户不支持指定模型。普通 403、目录介绍文字、工具输出和模型正文不触发模型拒绝路由。
- 拒绝仅缓存账户与模型的组合两分钟，不把整个账户标成额度耗尽，不增加额度轮换次数。其他模型仍可使用；显式重新导入凭据或套餐变化会清除旧证据。
- 所有参与账户都明确拒绝时进入“等待模型账户”。保留任务与会话，可直接换模型或点击“检查模型目录”重试；模型选择与任务启动发生竞争时不修改已运行的任务。
- 因模型拒绝受阻的既有 Goal 只恢复状态，不重置目标、预算和累计用量；用户暂停、预算停止和已完成状态不自动恢复。此组合有协议回归测试，本轮没有额外付费跑原生 Goal 模型拒绝测试。

## 真实小额测试

使用独立 QA profile，从已授权的 QA 加密凭据库只读获取 access token。不复制 refresh token，不修改用户原客户端。

`qa-output/model-rejection-live-report.json`：实际原生 CLI 接受一个不存在型号的轮次后，由后端明确返回模型不支持错误，原生状态为 `failed`。报告没有返回该失败尝试的 Token 计量，不能将其声称为免费调用。

`qa-output/model-recovery-live-report.json`：实际 Scheduler → CliWorker → 后端闭环通过。一次不支持模型的尝试进入模型等待，账户仍为 `ready`；切为实际目录中的 `gpt-6-luna / low` 后，同一任务和原生 thread 完成并返回 `MODEL_RECOVERY_LIVE_OK`。共两次 turn/start（一次失败、一次成功）、额度轮换计数 0。成功轮次报告 15907 Token，其中输出 10；额度窗口前后均显示使用 0%，这是取整读数，不代表无消耗。

本轮只有一个账户参加真实模型恢复测试；不同权限账户间的自动路由由状态机测试覆盖，没有冒充双账户真实权限差异测试。模型列表界面仍取当前元数据连接返回的目录，本版没有宣称实现跨账户目录合并。

## 问题选项卡

当前工作流包括聊天待答提示、右侧“问题”标签、最多三个问题、选项/允许的自定义回答、补充说明、私密输入、多问题完整校验、内存草稿及子代理来源。

回答发送后等待原生请求确认，不提前显示成功；过期请求不能继续提交。重启后保留已回答/失效记录，旧进程的未回答 RPC 请求不能跨进程继续提交。私密回答不写入历史。

已有真实 CLI 测试 `questions-live-report.json` 通过界面提交选择/自定义回答，并核实同一原生轮次收到两个值后继续；第二轮停止与冷重启核实失效记录。此次界面回归不再新增模型调用：`questions-ui.cjs` 检查草稿、完整提交、等待确认和过期状态；`questions-native.cjs` 在真实 Electron 中回放这份已验证历史，检查简中、繁中和英文。
