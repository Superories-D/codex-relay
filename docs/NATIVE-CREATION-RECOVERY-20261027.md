# 桌面新聊天的自动确认

聊天输入框创建普通聊天或独立审查时，会先保存完整请求和 UUID，再向主进程提交。原文、附件引用、模型与推理强度、沙箱、规划/多代理设置、验收条件和最终工作目录一起冻结。IPC 超时、回复丢失、切换聊天、界面重载或应用重启后，后台继续核对同一编号，不要求用户点击继续，不根据后来修改的输入重新创建。

同一输入框仍有待确认创建时，发送按钮会暂时禁止重复创建，正文仍可编辑。后台确认成功不会切走用户正在编辑的另一段对话；回到新聊天输入框可以打开已经创建的聊天。立即确认成功、且用户没有切换或留下新草稿时，会直接进入新聊天。连续按两次 Enter 也只进入一次项目准备流程。

## 接受证明与取消

主进程沿用调度器的持久创建回执，返回原任务 UUID。再次确认已经创建的任务不会重置状态、重新入队，也不会撤销后来的暂停。请求绑定与追问相同的持久应用数据身份；切到另一套数据时不会投递旧请求。

“停止确认并保留草稿”与同编号的在途创建串行。创建已经发生时显示原接受结果；尚未发生时先保存取消摘要，之后的重载或重启仍拒绝该创建。停止确认不能撤回已经接受的任务，需要停止执行时使用任务暂停/取消。取消记录只保存编号和摘要，不另存任务正文。

确认成功只清理原请求的草稿及匹配附件，随后才移除待确认记录。草稿清理与确认编号一起持久保存；最后一步失败后重试，不会清掉后来写下的新草稿，包括与原文恰好相同的文字。验收草稿也只在仍与已提交版本一致时清理。存储无法写入时，不发送未保存的新意图；记录损坏时保留原数据并显示问题。

## 范围与验证

每类待确认请求最多 100 条，后台使用两个工作槽，以 3–60 秒退避核对。初始化暂时失败会自动重试。创建持续目标、工作树准备本身、立即补充和其他原生操作仍使用各自入口；本功能不盲目重放这些操作，也不承诺模型执行外部动作恰好一次。

后端检查包含调度器/存储完整重启、并发同编号、后续暂停、不同数据身份、输入冲突、存储故障、真实状态文件落盘后确认丢失、取消与创建同时到达，以及取消落盘确认丢失。前端检查覆盖冻结输入、超时、重载、草稿清理失败、同输入框重复提交、取消和损坏记录。生产渲染器使用模拟持久 IPC，在简体、繁体、英语和日语下验证完整流程；英语用 150% 缩放等效视口检查。没有原生 Windows 安装器执行或模型调用。
