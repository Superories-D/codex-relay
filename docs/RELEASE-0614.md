# v0.6.13–0.6.14：实际安装实例的导入与 Team 账号修复

持续功能 Goal 保持暂停。本轮修复用户当前安装实例的问题，关键节点 commit + push。

## 导入只有少量记录的原因

新版 Desktop 的 `state_5.sqlite` 索引了 651 条会话，历史采用 `history_mode=paginated`，完整内容在 `thread_history_1.sqlite`。旧导入器只扫描 JSONL，因此仅找到少量会话；大量 Guardian 审核记录又挤占侧栏，让主会话更难发现。

导入器现在同时读取原生日志和 SQLite 索引，以分页数据库覆盖不完整的日志。数据库通过只读连接和 SQLite 在线备份制作受保护的独立副本，不复制源认证文件和 Goal 数据库。消息转换与媒体复制在 Worker 中执行，分批提交，支持进度、取消和重复跳过。已导入的旧记录原地更新，保留任务 ID、固定和归档状态；已在本客户端续接的会话不会被覆盖。

复制的元数据会重定位 rollout 路径，同时按原字节复制可用日志并保留规范文件名与祖先边界；旧导入副本也会补全。避免续接时写入源客户端日志。源数据库、认证缓存和原始日志不会被导入器修改。Desktop 专属工具、只读子代理和后台审核保留明确的兼容性提示。

本机 632 条会话的源日志或必需祖先不可用，保留完整缓存供阅读并标记只读。不能把缓存展示成功当作原生上下文一定可续接。可用日志先在私有副本内通过原生 CLI 重建分页投影，关闭 Goal 自动轮次，不发送模型输入；导入 Worker 再同步界面记录。消息键包含轮次，避免不同轮次同名条目互相覆盖；重新生成界面记录时保留已复制的图片。已导入会话的分页投影后续补全时可原地刷新，不再分配一份数据库副本。

项目与主会话优先显示；子代理和后台审核收进独立折叠分组。统计区区分发现总量、新增、更新及已存在。中文和表情直接按 UTF-8 读取；完整 JSON 提供代码排版和复制，终端控制序列仅在展示时移除。极长输出采用有标记的 UI 预览，原始完整记录可导出，避免静默丢失内容。

## 同一 Team 的第三个账号被合并

旧逻辑把 `chatgpt_account_id` 同时当工作区 ID 和唯一用户身份。同一 Team 的不同用户共享工作区 ID，登录另一个成员时会更新已有记录，表现为浏览器成功但没有第三张卡片。这不是账号数上限。

v0.6.14 保留原工作区 ID 供 CLI 鉴权，另从 JWT 用户主体读取 `userIdentity`，去重依据为“工作区 + 用户”。现有记录从各自加密 vault 补全用户元数据，保留账号 UUID 和任务引用。登录、备份预览、重复项判断、刷新、Desktop 退出回写和恢复均检查用户身份；同团队其他用户的残留缓存不会写入当前账户。

登录完成会明确反馈新增还是更新及实际邮箱，另提供官方设备验证码入口。旧版已经覆盖的另一位用户的凭据无法凭空恢复，需要该用户重新登录；修复后将保留为独立账户。

回归覆盖同 Team 三名用户分别保存、同用户重复登录更新、同用户不同工作区分开、旧 vault 元数据迁移，以及拒绝同 Team 其他用户的缓存。不会用伪造凭据测试生产登录，也未声称替用户完成第三个邮箱的实际授权。
