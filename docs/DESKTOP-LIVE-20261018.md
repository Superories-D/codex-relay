- 父任务收到结果后返回 `SUBAGENTS_OK A=42 B=42`。
- 两个子线程各自有独立聊天记录，未作为父线程回答写入父聊天。
- 第二轮在同一父线程中恢复，正确回复此前要求记住的短语。
- 刷新客户端后，代理列表、任务内容和子线程实际回答仍可显示。
- 测试结束时两个账户仍可用，没有刻意耗尽额度；五小时窗口使用量约 1% 和 38%。第二个账户的使用量包含测试前已有使用，不能归因于本次测试。
- 此次没有验证运行中子代理的人工发消息、停止，或多层子代理的跨账户恢复。这些仍列入后续验收。

第一次 UI 截图脚本使用了错误的按钮名称，发生定位超时；模型任务本身已经完成。修正定位后使用原任务继续验证，没有重新派出代理。未将脚本超时表述为模型失败。

本地证据：`qa-output/desktop-subagents-report.json`、`qa-output/desktop-live-subagents.png`。子代理执行使用的是 CLI 的真实工具能力，客户端依据实际协议事件跟踪父子线程。公开协议说明见 [app-server](https://learn.chatgpt.com/docs/app-server)。

## 顺滑测量

测量不是所有硬件上的性能承诺；记录的是本机生产构建在本轮负载下的结果。

`scripts/qa/chat-performance.cjs`：1 万条历史、约 20.8 MiB，首次读取约 60 ms，缓存读取 P95 约 0.4 ms，追加并读取 P95 约 2.3 ms。每次最多返回 80 条消息，追加采用增量缓存，外部修改仍使缓存失效。重复计划记录、实时消息完成和外部修改的一致性由回归测试覆盖。

`scripts/qa/agent-ui.cjs`：显示 80 条较长 Markdown 消息，20 Hz 推送、共 40 次更新，同时输入 144 个字符。输入至下一帧 P95 约 14 ms，未记录到超过 50 ms 的长任务；向上阅读位置未被拉回底部，切换聊天后草稿和阅读位置恢复。该回归采用模拟流式消息，真实 PTY 和子代理有独立验收。

本地性能报告：`qa-output/chat-performance-report.json`、`qa-output/agent-ui-report.json`。继续补测更长的单条回答、更多子代理、终端同步输出和不同窗口缩放。

## 历史轮次与编辑分支

`scripts/qa/history-native.cjs` 继续使用此前已经完成的真实会话，通过原生 Electron 与 CLI 公共协议执行本地历史操作，没有开始新的模型轮次。

- 从第二轮进入“编辑并创建分支”：新分支只保留第一轮，第二轮原文进入草稿，原聊天仍有完整两轮。
- 新分支的聊天记录包含第一轮实际回答，排除了第二轮回答。
- 由分支继续创建分支，仍能读取保留的上下文；从第一轮编辑会创建空分支。
- 应用退出重启后，新分支保留一轮，原聊天仍保留两轮。

新版 CLI 的分支文件可能只有 `session_meta` 和设置记录，历史通过 CLI 数据库引用父线程。本次使用原生 `thread/fork` 与 `thread/revert`，保留受管运行目录中的线程家族，避免复制元数据后丢失上下文。编辑分支保留项目当前文件，不宣称撤销此前文件修改。单个运行目录中的维护与执行继续由串行调度保护。
