# v0.1.1 深度调试记录

日期：2026-10-14。针对“额度自动暂停不能视为完成”，逐层检查 Scheduler、账户凭据、RPC、进程关闭、客户端 rollout/CDP 与 CLI 查看器。

## 修复与证据

| 发现的问题 | 修复与回归证据 |
|---|---|
| app-server 的 `error` 通知撞上 Node EventEmitter 的特殊事件，可直接抛出异常 | 协议错误仍交给 worker 分类，命名事件改为 `rpc:error`；RPC 单测与真实子进程集成覆盖额度错误后伪成功事件 |
| 多处同时关闭同一进程、已被信号终止的进程仍被判为活进程 | close 单次执行且失败可重试；识别 signalCode；输送管道 EPIPE 通知 worker，避免永久 running |
| 关闭 Relay 时账户查询尚未返回，返回后可能继续派发 | 等待在途 tick、当前任务和账户写回；每次异步查询后重查关闭/恢复门禁 |
| 完成的任务可经 pause/resume 重新执行 | completed/cancelled 为不可操作终态；另行验证完成落盘与应用退出的竞争 |
| 某账户准备中的刷新与桌面凭据接管、删除、导入竞争 | 同账户串行锁内重查占用；桌面租用等待之前的刷新结束；重复身份导入去重 |
| 刷新或登录成功后写入账户库失败可能丢失唯一新凭据 | 加密写回成功后才清理；保留未写回的登录缓存；无时间戳刷新缓存优先恢复，显式重新登录则覆盖残留旧缓存 |
| 新 CLI 线程在首轮发送前可能尚无 rollout | start/archive/unarchive/resume 后才 checkpoint；两种 worker 复用同一持久化步骤 |
| 终止时额度未知、只有 commentary 仍可能被当作完成 | 正常终态之外，要求有最终答复与有效额度复查；额度中断证据始终优先 |
| 客户端点击线程成功但页面未切换、旧终止事件误报 | 验证活动线程；要求本轮 task_started 和匹配 turn_id；真实 Chromium 验证选择、输入与歧义拒绝 |
| 初始化清理或进程停止失败后，恢复门禁未覆盖所有异常路径 | 保留进程记录/凭据，持久化 recoveryRequired 并冻结整个队列；客户端保留 bootstrap 句柄且核对关闭回执 nonce |
| 等待旧的长重置时间时，新可用账户不能及时唤醒任务 | 每次调度检查新鲜可用账户；仍须服务器确认，时间经过不能自行补满额度 |
| CLI 查看器失联以成功退出，长命令可能被空闲超时打断 | 意外断连 exit 1；仅无待处理命令时应用空闲超时；断连后不执行排队命令或遗留观察监听 |

## 验证层次

1. TypeScript strict 与 esbuild 构建；81 项 Vitest 检查。
2. 真正启动 Node 子进程，通过 JSONL 执行实际 Rpc → CliWorker → Scheduler 链路。第一账户发送额度错误和伪完成通知，第二账户接续同一已持久化线程；核对原始提示、继续提示及进程占用记录清理。对端是确定性测试程序，不是已登录 Codex 服务。
3. 实际 CLI 子进程与命令服务器验证认证、观察通知和意外失联退出。当前 Linux 容器拒绝 AF_UNIX 监听，测试专用适配器改用环回 TCP；生产仍使用 Windows 命名管道，该 Windows 传输未实测。
4. 实际 Cdp 类连接独立 Chromium：未选中线程拒绝确认、选中线程验证、中文多行输入、已有草稿保留、多编辑器/多页面拒绝。
5. 对照官方 0.162.1 协议生成物与对应 Git 标签源码审查。实际匿名 initialize/account/read/model/list 有响应；thread/start 在 30 秒、120 秒探针中未完成。追加调试日志显示初始化中的插件网络请求失败，但没有充分证据把线程超时唯一归因于此。没有将真实线程创建与账户轮换写为实测通过。

## 结论范围

当前自动化检查覆盖的已发现问题均已修复。仍不能据此保证 Windows 安装包、DPAPI、命名管道、官方客户端具体版本、真实账户登录/刷新/限额切换全部正常。Windows 验收项保留在 `WINDOWS-ACCEPTANCE.md`；桌面适配继续标记为实验功能。

不会将静默、额度中断、网络失败或未知终止状态当作完成。若无法确认原进程退出，任务宁可等待检查，也不自动创建重复执行实例。已经脱离父进程树的外部后台程序不在本工具可证明的进程控制范围内。
