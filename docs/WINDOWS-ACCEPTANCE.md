# Windows 验收清单

以下均为待执行的真机验收项。本次交付没有把它们标记为已通过。先用可丢弃的小型 Git 工作目录，不需要为了测试故意消耗真实额度。

## 安装和账户

- [ ] Windows Actions 构建通过，NSIS/便携版均能启动；托盘图标可见，关闭窗口后仍运行，从托盘退出可结束。
- [ ] CLI 可执行路径含中文/空格、npm codex.cmd 两种路径可用，未通过 shell 拼接执行用户输入。
- [ ] 浏览器登录和设备码登录均完成；不同账户正确分开，同一个账户重复登录更新原记录。
- [ ] 导入官方 auth.json；API key 格式被拒绝；账户库不是明文，暂存目录 ACL 仅当前用户与 SYSTEM。
- [ ] 账户顺序、启用状态、备注/模型信息、5h/周窗口与官方读数一致。
- [ ] 新受管配置的 Windows 沙盒能设置成功；失败时不扩大权限。

## CLI 接力（最高优先级）

- [ ] 创建会写入少量文件的任务，观察 thread ID 和 turn ID 被保存。
- [ ] 有真实到达限额的账户时，检测 `usageLimitExceeded` 或 100% 使用率；任务进入暂停/轮换而非完成。
- [ ] 原进程确认停止后才出现新进程；工作目录没有两个 Codex 写入进程并行。
- [ ] 新账户恢复相同 thread ID，继续原始任务而非从头重复已完成的操作。
- [ ] 每个账户都耗尽时保持“等待额度恢复”；在重置前不启动、到点先重新读额度，恢复后自动继续。
- [ ] 仅周额度耗尽、仅 5h 耗尽、两个窗口都耗尽均正确；无 5h 窗口的账户不被误判为耗尽。
- [ ] 正常完成计为完成；任务内容提到“Usage limit exceeded”但不是错误时，不误判为额度中断。
- [ ] 命令/文件审批和模型追问可处理；拒绝与取消不会被自动重复提交。
- [ ] 手动暂停后不自启；恢复、取消、关闭再打开均保留正确状态。

## 官方客户端（实验）

- [ ] Store 安装和手动选择 executable 的启动路径可行；独立 Electron/Codex profile 生效。
- [ ] 你原本的官方客户端窗口与默认 .codex 登录状态未被改变。
- [ ] 受管标题的线程可见，定位正确，输入框为空时发送；其他窗口和旧草稿不被操作。
- [ ] task_started 来自预期 rollout，真实 turn_id 被保存，正常和限额自动停止分别正确分类。
- [ ] 停止按钮不匹配时进入待处理，不盲目换号；更新应用后选择器失效同样保留任务。
- [ ] 客户端意外关闭后检测连接丢失，不无限显示运行中。

## 故障和恢复

- [ ] 离线、HTTP 429 服务节流、账户过期、模型权限不同：分类与提示正确，429 不直接视作订阅额度耗尽。
- [ ] 停止 ACK 后不出现 terminal：进入待处理，第二个任务不启动。
- [ ] 运行时强制退出 Relay 后重启：全队列冻结，旧 CLI 仍在运行时拒绝继续；结束旧进程后可从相同会话恢复。
- [ ] 客户端刷新过令牌后崩溃：恢复时先验证实例、保存更新凭据，再开始新会话。
- [ ] 休眠唤醒重新读额度；未知重置时间退避，不出现高频循环。
- [ ] CLI watch 等待限额恢复时不断开，不报告成功；终端 Ctrl+C 不停止受管任务。
- [ ] 导出日志没有 OAuth token、refresh token 或 API key；任务输出包含的项目内容按需要人工检查。

## v0.1.1 回归重点

- [ ] 新建任务在首轮发送前暂停，继续时仍使用原 thread，不报线程不存在。
- [ ] 出现额度 error 后又收到 completed，必须继续轮换，不能显示成功。
- [ ] 最终额度复查失败、只有 commentary 或缺少有效最终答复时，保留“需要处理”。
- [ ] 全部耗尽后添加或重新启用一个已核实可用账户，无需等到旧的周重置时间。
- [ ] 开始账户刷新时立即切入客户端任务，刷新完成后才交出独占权；同时删除/导入该账户应被阻止。
- [ ] 初始化过程停止失败、客户端启动回执不匹配，均冻结队列；重启后仍不能绕过检查。
- [ ] 连点暂停/继续，以及任务完成落盘时退出，均不产生第二个受管任务。
- [ ] 客户端点击会话后页面未切换或旧 task_complete 到达，不得向错误会话发送或标记成功。
- [ ] CLI watch 连接被 Relay 意外关闭，退出码必须为 1；命名管道的认证失败不执行命令。
