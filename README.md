# Codex Relay

正在进行 Codex Desktop 的完整功能与界面打磨，进度、已验证工作流和待补项目见 [桌面功能对齐记录](docs/DESKTOP-PARITY.md)。当前源码包含下一阶段的工作空间、子代理与 PTY 终端改造；已发布到本机 `release/` 的稳定构建仍为下述 v0.5.0。

**当前版本：v0.5.0 Windows Agent 客户端。** 基于官方 Codex CLI，提供项目与对话侧栏、多轮聊天、执行记录、审批、附件、排队发送和自动账户接力。额度不足时确认原进程停止，再使用可用账户继续原会话；全部账户受限时等待并复查服务器额度。

模型选择器按登录账户的实际 CLI 目录展示模型名称、可用思考档位与默认强度，使用弹出面板、分档滑杆和重置按钮。支持扫描 CLI / Desktop 本地会话与归档，批量导入为独立副本并恢复最后的模型与强度。Desktop 专属工具、子代理和外部历史依赖会显示兼容性说明。

Windows 构建、158 项测试、三种窗口宽度的界面检查及最终便携启动器检查通过。真实账户用 3 轮小任务验证了文件编辑、同线程跨账户追问和历史副本续聊，未故意耗尽额度。操作范围与验证记录见 [Agent 使用与验收](docs/AGENT-V050.md)。便携版、安装版位于 `release/`。

此前 Windows 启动问题的修复见 [Windows 本机调试记录](docs/DEBUG-WINDOWS-20261017.md)；此前的代码生成、6 项真实测试、命令审批、暂停恢复验收见 [CLI 真实账户验收](docs/LIVE-CLI-20261017.md)。

本版增加**已打开的 Windows Codex CLI / 官方客户端会话接入**：可以保留原窗口监控，额度中断后交接，也可以立即交接。交接后在 Relay 管理的 CLI 或独立客户端中继续原线程。详细步骤和适用范围见 [已有会话接入](docs/EXISTING-SESSIONS.md)。此前参考 CodexPilot 的导入与完成检查继续保留，取舍见 [参考实现审查](docs/REFERENCE-REVIEW.md)。

## 功能

- 扫描默认或指定 CODEX_HOME 的本机会话，显示任务、目录、状态及关联进程；确认范围后接入已有任务。保留原 thread ID、原始目标、工作目录和可读取的模型配置；交接前结束核实过的原 Codex 进程树。

- 官方 Codex 浏览器登录、设备码登录、导入本机登录或账户备份；支持 `auth.json`、JSON 数组/`accounts` 包装、平铺字段、`credentials` 对象和 JSONL。导入前逐条预览、选择，重复/无效条目跳过；不收集账户密码。
- 5 小时、每周及其他服务端额度窗口；缺失窗口显示未知，不误认为剩余为零。
- 有序账户池、启用/禁用、调整顺序、任务队列、手动暂停/继续/取消。
- 额度中断优先于 `completed` 状态：结构化额度错误、额度事件及最终复查都会参与判断。缺少可核实额度或最终答复时保留任务，不报成功。
- 可选完成标记：只有最终答复最后独立一行匹配指定标记才通过附加检查；缺失时接续原会话，默认最多自动补完 3 次，达到上限进入“需要处理”，避免无限消耗额度。额度中断仍优先处理。
- `turn/interrupt` 只是停止请求，等待终止事件并关闭原进程后才允许切号。
- 所有账户耗尽：同一账户取所有受限窗口中最晚的恢复时间，账户间取最早可恢复时间；到点重新读服务器额度。没有重置时间时退避重试。
- 持久化 thread ID、turn ID、任务状态；继续时保留原始任务上下文和工作目录。刷新令牌由单一账户配置负责，避免多个进程竞争刷新。
- Windows DPAPI 加密账户库，受管目录 ACL；渲染页面没有 Node 权限。本机命名管道为 CLI 提供入口。
- 托盘驻留、运行时防休眠、唤醒后重新核实额度、脱敏诊断日志。
- 100ms 合并状态推送、日志容量限制、协议帧与请求队列上限；有可用账户时优先启动，避免先等待其他账户的后台探测。
- 按操作显示进度、后台连接提示、任务/日志筛选、可滚动弹窗和窄窗口布局；后台核实额度时仍可浏览页面。

## 在 Windows 构建

环境：Windows 10/11 x64、Node.js 22 或更新的受支持 LTS、官方 Codex CLI。客户端模式还需要安装官方 Codex Windows 应用。研究时 npm 的 Codex 版本为 `0.162.1`；采用了实验性外部账户令牌接口，旧版本可能不兼容，详见 [兼容性与研究记录](docs/RESEARCH.md)。

```powershell
npm install -g @openai/codex@0.162.1
npm ci
npm run check
npm run dev
```

在界面“设置”中确认 `codex` 可找到；也可选择 `codex.exe` 或 npm 的 `codex.cmd`。自定义任意批处理文件不是受支持的 CLI 路径。首次运行受管任务时，Relay 请求官方 CLI 配置非提权 Windows 沙盒；配置失败会保留任务，不会自动放开权限。

生成安装包：

```powershell
npm run package:win
```

产物位于 `release/`，含 NSIS 安装版和便携版。Gitea 配置位于 `.gitea/workflows/`：推送执行构建/测试，Windows 打包为手动工作流，需要你所在服务上有对应 runner。Windows 工作流的 artifact 上传要求 Gitea Runner 3.x、启用 `patch_actions` 并注册 `windows-latest` 标签；没有 runner 时可直接执行上述本地命令。保留 `.github/workflows/windows.yml` 供 GitHub 环境使用。本次已在 Windows 实际打包和启动验证，安装向导与远程工作流未执行；产物未进行发布者证书签名。

## 第一次使用

1. 在设置中检查运行环境并保存正确的 CLI 路径。添加你有权使用的 ChatGPT 账户，或在“账户轮换”导入本机登录/备份；预览中勾选需要的条目再确认。添加后等待额度核实，并按需要排序。
2. 点击“新聊天”，选择项目目录并发送目标。默认使用 CLI、项目内读写和必要时请求审批。完成后在同一输入框追问，运行中可排队发送或补充到当前轮次；也可从“任务队列”使用原任务管理界面。
3. 点击输入框下方的模型与强度按钮，点击模型名称切换模型，用分档滑杆设置思考强度，右上角重置为该模型默认值。模型来源为账户实际权限；账户间权限不一致时提示处理。需要附加完成检查时，在原“新建任务”的“完成校验”填写标记和自动补完次数（0–10）。
4. 任务运行中，如遇额度耗尽，状态会依次经过暂停、轮换、继续。若全部耗尽，界面显示“等待额度恢复”和下次核实时间；这不是完成状态。
5. 文件/命令审批与模型追问在 Relay 中处理；客户端模式的审批在官方客户端中处理。无人值守任务可选“不请求审批”，超出沙盒权限的操作会被拒绝。
6. 关闭窗口后仍在托盘运行。需要退出时使用托盘“暂停受管任务 / 监控并退出”。未交接的普通窗口继续由原 Codex 运行；Relay 只暂停对它的监控。

导入历史：侧栏“导入 CLI / Desktop 对话”→扫描默认目录或添加其他 Codex 数据目录→导入全部或选中记录。归档记录可从“已归档会话”查看。云端未落地的会话不会自动下载。会话顶部“CLI 能力与配置”可操作公开协议中的模型、Skills、MCP、插件、配置、上下文压缩等能力；当前不是 CLI 全部交互功能的完整复刻，具体边界见 [Agent 使用与验收](docs/AGENT-V050.md)。

账户认证信息留在本机；Codex 本身仍按其产品行为与 OpenAI 服务通信。默认不改写你现有的 `%USERPROFILE%\.codex`。受管目录位于 `%APPDATA%\Codex Relay`，安装版和便携版默认共用这个目录。

## 接入已经打开的普通窗口 / 终端

1. 先在 Relay 添加接力账户，并暂停或取消其他 Relay 队列任务。
2. 点击右上角「接入已有会话」→「扫描本机会话」。默认读取 `%CODEX_HOME%` 或 `%USERPROFILE%\.codex`；可指定目录或按 thread UUID 查找。
3. 选择当前任务，检查 PID、程序路径及实例范围。确认允许在交接时结束所列 Codex 实例和子进程。
4. 选择「额度中断时自动交接」或「立即交接并继续」，并选交接后用 CLI 还是官方客户端。
5. 原任务额度耗尽后，Relay 保存完整历史、确认原进程停止，使用可用账户恢复原线程。所有账户耗尽则等待并复查额度，不记作完成。

**桌面交接会关闭选中的整个 Codex 实例，包括它的其他聊天任务。CLI 交接会结束目标 Codex 与子进程，保留终端宿主窗口。** 原始会话文件与登录文件不被改写；交接后在 Relay 或新的受管窗口操作，不要同时恢复原任务。

仅支持 Windows 本地、可读取 rollout 的主会话；WSL、远程、云端、IDE 扩展专用会话和依赖其他线程/应用专用工具的记录不在本版保证范围内。进程归属无法确认时会保留任务并提示处理。详细说明见 [已有会话接入指南](docs/EXISTING-SESSIONS.md)。

## 从终端创建或查看任务

先保持 Relay 桌面程序运行：

```powershell
node scripts/relay.cjs run --cwd "C:\Projects\demo" --prompt "完成账户管理功能并验证"
node scripts/relay.cjs run --cwd "C:\Projects\demo" --prompt-file "C:\Tasks\task.txt"
node scripts/relay.cjs run --cwd "C:\Projects\demo" --prompt "完成任务并检查结果" --completion-marker "[TASK_DONE]" --completion-retries 3
node scripts/relay.cjs sessions
node scripts/relay.cjs attach --session <原会话UUID> --when quota --mode cli --allow-stop
node scripts/relay.cjs handoff --id <Relay任务UUID>
node scripts/relay.cjs status
node scripts/relay.cjs watch --id <任务UUID>
node scripts/relay.cjs pause --id <任务UUID>
node scripts/relay.cjs resume --id <任务UUID>
node scripts/relay.cjs cancel --id <任务UUID>
```

打包安装后脚本在程序的 `resources\relay.cjs` 中。Ctrl+C 只断开终端查看器，任务继续由 Relay 管理。审批可在 Relay 窗口中完成。查看器意外失联以非零退出码结束，不能当作任务成功。`run` 创建受管任务；`attach` 接入已有原会话，`--allow-stop` 表示允许交接时结束已核实的 Codex 实例及其子进程。没有该参数时只显示进程范围，不执行接入。`handoff` 让已接入、尚未交接的任务立即迁入 Relay；任务 UUID 与原会话 UUID 不同。

## 官方客户端模式

先在设置中自动检测官方客户端并保存，再在新任务中选择“官方客户端（实验适配）”。Relay 用隔离的 Codex 配置和 Electron 数据目录启动单独的官方客户端实例，定位专属任务会话，通过可见输入/发送/停止控件操作，并读取该会话的真实 rollout 事件确认执行状态。

运行时可点击“打开受管客户端”和“检查适配”。发送/停止会同时核实目标会话；发送前持久化待确认标记，避免把丢失回执当作从未开始。详细操作与故障说明见 [Desktop 适配指南](docs/DESKTOP.md)。

如果客户端忽略隔离目录、禁用调试端口、修改页面结构、出现多个候选页面或没有唯一匹配控件，会停止自动操作并保留任务。可以在设置中调整 CSS 选择器。**无法保证所有官方客户端版本都可自动控制；请先完成 [Windows 验收清单](docs/WINDOWS-ACCEPTANCE.md)。** 新建受管任务保持实例隔离。已有普通窗口通过上面的「接入已有会话」先监控、再停止选中的原实例并迁入独立实例；不会在未启用调试端口的原窗口里注入控制。

## 恢复、数据与限制

- 异常退出后任务进入“需要处理”，全队列暂时冻结。点击继续/取消时验证原实例；CLI 旧进程仍存活则拒绝重复启动，需先结束对应进程。客户端使用 PID、可执行文件路径、独立 profile 和启动回执共同校验，只操作已确认归属的实例。
- DPAPI 凭据通常绑定 Windows 用户。不要直接把账户库复制给另一个用户或电脑；请重新登录。Codex 必需的临时 `auth.json` 仅在受限目录内出现，刷新后先加密落盘再清理；崩溃时可能保留用于恢复。
- Relay 保持会话和文件，不提供外部操作的 exactly-once 保证。恢复提示会让 Codex 检查现有结果，避免重复提交或发布；重要外部操作仍应使用审批。
- “完成”要求 Codex 正常结束该轮、有最终答复、终止时成功核实所选额度桶，且没有额度中断证据。它不是对自然语言验收标准的形式化证明，也不会绕过用户输入或审批。
- 未实现并行任务、云端任务接管、任意第三方客户端接管或系统服务模式。已有会话一次接入一个，未完成交接时阻止其他 Relay 队列启动和账户刷新；其他手动启动的外部任务仍须用户自行管理。
- 不创建新账户、不修改服务器额度；只调度已登录且服务器确认可用的账户。
- 日志可能包含任务输出、路径与代码。导出前应按自身项目保密要求检查。
